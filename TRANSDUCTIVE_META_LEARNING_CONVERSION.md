## 🔍 **How It Works**

### **Step 1: Generate Pseudo-Labels**

```python
query_distances.shape = (N_query, num_classes)  # Distances to each prototype
query_pseudo_labels = torch.argmin(query_distances, dim=1)  # Index of nearest prototype
# Example output: [0, 1, 0, 1, 1, 0, ...]  # Indices: 0 = first prototype, 1 = second prototype
```

**What this does**:
- Finds which prototype is closest to each query embedding
- Creates pseudo-labels: "this query sample is closest to prototype 0, so assign it class 0"
- `.detach()` prevents gradients from flowing through pseudo-label generation

---

### **Step 2: Use Pseudo-Labels for Loss**

```python
query_logits = -query_distances  # Shape: (N_query, num_classes)
query_loss = F.cross_entropy(query_logits, query_pseudo_labels)  # Uses pseudo-labels
```

**Cross-entropy expects**:
- `query_logits`: (N_query, num_classes) - logits for each class
- `query_pseudo_labels`: (N_query,) - class indices [0, 1, 2, ...]

**This is correct** because:
- `query_distances` has shape (N_query, num_classes) where columns correspond to prototypes
- `torch.argmin(query_distances, dim=1)` gives indices [0, 1, 2, ...] matching the prototype order
- These indices directly correspond to class indices for cross-entropy loss

---

### **Step 3: Gradient Flow (Important!)**

**Gradient computation**:
```
query_embeddings (from model.forward(query_x))
  ↓
query_distances = torch.cdist(query_embeddings, prototypes)
  ↓
query_logits = -query_distances
  ↓
query_pseudo_labels = torch.argmin(query_distances, dim=1).detach()  ⚠️ DETACHED
  ↓
query_loss = F.cross_entropy(query_logits, query_pseudo_labels)
  ↓
total_loss = support_loss + query_loss
  ↓
total_loss.backward()
```

**Key point**: 
- ✅ Gradients flow through: `query_logits` → `query_distances` → `query_embeddings` → model parameters
- ✅ Pseudo-labels are **detached**, so gradients don't flow through the argmin operation
- ✅ This is correct - we treat pseudo-labels as **fixed targets** (like self-training)

## ⚠️ **Important Notes**

### **1. Pseudo-Labels vs Ground Truth**
- **Training**: Uses pseudo-labels (from prototype predictions)
- **Evaluation**: Still uses ground truth `query_y` for accuracy/metrics (Line 1404)
- **Both**: Needed during development/testing to measure performance

### **2. Why `.detach()` is Important**
```python
query_pseudo_labels = torch.argmin(query_distances, dim=1).detach()
```

- `.detach()` treats pseudo-labels as **fixed targets**
- Prevents gradients from flowing through the argmin operation
- This is standard in self-training / pseudo-labeling approaches
- Without detach, gradients would try to optimize the pseudo-label generation itself (incorrect)

### **3. Label Index Mapping**
```python
unique_labels = torch.unique(support_y)  # e.g., [0, 1] for binary classification
prototypes = [...]  # One prototype per unique label
query_pseudo_labels = torch.argmin(query_distances, dim=1)  # Indices: [0, 1, 0, ...]
```

- `query_pseudo_labels` are **indices** into the prototypes array: [0, 1, 2, ...]
- These correspond to `unique_labels[0]`, `unique_labels[1]`, etc.
- For binary: indices [0, 1] map to labels [0, 1] (Normal, Attack)
- This is correct for cross-entropy loss which expects class indices
